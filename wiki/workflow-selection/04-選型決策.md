# 04 選型決策：遇到什麼問題，怎麼選

| 遇到的情況 | 建議 | 依據 |
|---|---|---|
| 單次 LLM 呼叫＋檢索＋範例就夠 | 先不做 agentic system | [B] |
| 步驟固定、可事先拆好、要可預測 | 固定自動流（chaining／routing／parallelization） | [B][E] |
| 子任務數量與內容要看輸入才知道 | Orchestrator-workers | [B][E] |
| 步驟數無法預測、路徑寫不死、需要模型自己判斷 | 單一 Agent（工具迴圈，ReAct 式） | [B][D][E] |
| 不同部分需要不同指令、工具或政策，且拆開能改善隔離或可讀性 | Multi-Agent（handoffs 或 agents-as-tools） | [C] |

## 選型三原則
1. 由簡入繁：只在「能證明結果變好」時加複雜度。[B]
2. Agent 是有代價的：較高成本、錯誤累積，需要護欄與停止條件。[B]
3. 拆 Agent 要有理由：契約（指令／工具／政策）改變了才拆。[C]

## 常見誤解（驗收提醒）
- 「固定流程不能用工具或記憶」→ 錯。這只是 n8n chain 節點的產品限制 [A]；一般 workflow 的 LLM 可帶工具與記憶 [B][E]。
- 「Agent 越多越強」→ 不一定，太早拆反而增加 prompt、trace 與核准點。[C]

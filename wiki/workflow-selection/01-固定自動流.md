# 01 固定自動流（Workflow）

## 定義
- 預先決定的程式路徑，照固定順序執行。[B][E]
- 優點：對定義清楚的任務，提供可預測性與一致性。[B]

## 常見模式（[B] 與 [E] 都列出同一組）
| 模式 | 做法 | 適合時機 |
|---|---|---|
| Prompt chaining | 每一步處理上一步輸出，可在中間加程式檢查（gate） | 任務能乾淨拆成固定子任務；用延遲換準確度 [B][E] |
| Routing | 先分類輸入，再導到專門流程 | 有明確類別且分類夠準，例如客服分流 [B][E] |
| Parallelization | 子任務同時跑（sectioning）或同任務跑多次投票（voting） | 要加速、或要多個觀點提高信心 [B][E] |
| Orchestrator-workers | 中央 LLM 動態拆任務、派給 worker、再彙整 | 子任務無法事先預測，例如改多個檔案的程式任務 [B][E] |
| Evaluator-optimizer | 一個產生、一個評估回饋，循環改進 | 有清楚評估標準、反覆修改有明確價值 [B][E] |

## 以 n8n 為例（產品定義，只適用 n8n）
- 在 n8n 中，**chain** 是「一串 LLM 呼叫，不帶工具也不帶記憶」；Basic LLM Chain 節點不支援記憶與工具。[A]
- ⚠️ 這是 n8n 對自家 chain 節點的定義，**不能推論成所有固定自動流程都不能用工具或記憶**。[B][E] 的 workflow 本身就允許 LLM 帶工具、檢索與記憶（augmented LLM），只是路徑是預先寫好的。

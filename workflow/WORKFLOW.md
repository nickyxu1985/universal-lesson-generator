# WORKFLOW — 通用教案產生器

> 範例主題：固定自動流 → 單一 Agent → Multi-Agent，怎麼做選型。受眾：國小／國中／高中。
> 作業步驟對照：取得資料 → 查詢 Wiki → 整理重點 → 檢查內容 → 產生簡報。

## 入口（首頁，CF Pages）

- 輸入主題、選受眾（國小／國中／高中）、按生成；底下顯示目前進度、已產生教案連結、取消按鍵。
- 送出先 POST 到同站 `/api/filter`，由 CF Workers AI 守門（18 禁／K-12 適齡／Prompt 注入偵測＋主題淨化）：主題合不合理、受眾有沒有選、有沒有重複。亂入直接否決，不燒後面整條線。
- 過了才 POST 春川 n8n webhook。瀏覽器前端不直接打 Workers AI，也不直接打 n8n。

## 0. 守門員（CF Workers AI）

- 只判斷過／不過，不做生成。輸入：主題＋受眾；輸出：pass／fail＋理由。
- 失敗：首頁顯示否決原因，流程結束，不進 n8n。

## 1. Ingest：找資料（Cue，經 mail）

- Agent 依主題自己找官方／技術文件，抓 5 個以上來源。範例主題起點：n8n、Anthropic、OpenAI、ReAct、LangGraph、Google（Hermes #1 已實測有正文；URL 見 `topics/topic.yaml`）。
- 檢查：HTTP 200、內文非空、跟主題有關、去重、官方優先。不合格換下一個，直到 5 個有效來源。
- 產出：來源清單＋抓取 log，貼回 Slack thread。

## 2. 整理進 LLM-Wiki：建知識庫（Hark）

- 把抓到的文件整理進自架 LLM-Wiki（repo 內 Markdown，按選型問題分章，不是按來源堆）。
- 檢查（Instinct）：每個主張都有來源、沒有腦補、重點都有覆蓋、結構完整。不合格回 1 補來源，或在 Wiki 內修正。

## 3a. 查 Wiki（Hark）

- 入口進來先跑這站：只看主題在 Wiki 裡有沒有、夠不夠，不看受眾。
- 有 → 往 3b；沒有／不夠 → 回 1 抓資料、2 進 Wiki，再回 3a。
- 「沒有／不夠」的標準寫死在 `agents/retriever.md`，不能由 agent 自己覺得有。

## 3b. 檢索＋整理成教案（Hark）

- 只讀 Wiki，依主題＋受眾檢索重點，整理成教案。同一 Wiki 生三種教案：國小／國中／高中用詞、例子、深度都不同。
- 檢查（Instinct）：覆蓋 Wiki 重點、沒有超出 Wiki 的內容、受眾看得懂、順序合理。不合格換關鍵字重檢索，或回 2 補 Wiki。

## 4. 教案 → HTML 簡報（Hark）

- 只讀教案，產出教學 HTML 簡報。簡報要讓選型例子從頭貫穿到底，產生器的概念才不會飄在空中。
- 檢查（Instinct）：每頁對得上教案、結構清楚、小白看得懂、圖表正確。不合格只重做壞掉那頁，或回 3 修教案。

## 完成

- 首頁出現已產生教案＋簡報連結；HTML 從暫存區轉進首頁前端（誰動手寫進 n8n 流程定義）。
- 全程留 log：ingest 紀錄、檢索關鍵字、驗證結果、重跑次數——就是作業要的檢查紀錄跟反思素材。

## 哪些步驟會重複執行（loop）

- 1 內部迴圈：抓一個來源 → 驗不過換下一個，直到湊滿 5 個有效來源。
- 2→1：結構化發現關鍵概念沒來源、或來源互相矛盾，退回補抓。
- 3b 內部迴圈：整理教案 → 對照關鍵問題看有沒有缺，缺了換關鍵字再抓。
- 3b→2／1：教案要的概念 Wiki 裡沒有，退回補結構化或補來源。
- 4 內部迴圈：一頁簡報生成 → 對照教案檢查，錯了重生那一頁。
- 4→3b：簡報對不上教案，問題在教案本身，退回修教案。

## 為什麼這樣設計

1. 越早上游攔錯越便宜：壞來源進 Wiki 會污染教案跟簡報，在 1 攔掉成本最低。
2. 有迴圈才會自我修正：直線跑下去一步錯、後面全錯。
3. 「檢查內容」那道門就是評分要的證據：產出檢查紀錄，保證簡報跟 Wiki 一一對應。
4. 每站只吃上一站的產出：問題只能回源頭修，不能在簡報偷補；換題目整條才能重跑，這就是複利。
5. 需要獨立檢查的流程，就不適合單一 agent 或 n8n 死流程：同一隻驗自己做的東西看不出盲點，所以驗證專職化（Instinct）。
6. 反例要寫進簡報：W10 產線看起來像固定 ETL，但模型變化快、每站都要判斷，所以 n8n 不是最佳解；相對地，Slack→n8n→叫封閉式 agent 那條是流程固定、內容不影響步驟，才是 n8n 的本行。兩者擺在一起就是選型指南。

## 複利

- 換主題＋受眾，其他流程不變，整條重跑一次就是證明。知識只存一次（Wiki），用法隨受眾換。
- 第二個題目重跑時只改 `topics/topic.yaml`／來源清單，逐站記錄人工介入次數，分開驗收「跑通一次」跟「真的可換題複用」。

## N8N 流程（春川，Nicky 重做）

- Webhook 接 CF 過濾後的任務 → 在 Slack 專用頻道開 thread，@Hark 查 Wiki → 沒有就發 mail 給 Cue，等回信貼回 thread → @Instinct 驗證，過了才往下 → @Hark 生教案＋HTML 到暫存區 → @Instinct 終驗，過了通知完成。
- 每站設 timeout，超時沒回就發警報（首頁紅字＋Slack 推播），不要靜靜卡住。
- @ 一次只 @ 一隻。Cue 用 mail，不在 Slack 裡 @（他沒接 Slack，@ 了也不會回）。
- n8n 有自己的 IP 跟網址，東京網站／CF Pages 只要打得到 webhook URL 就能用，不用同一台、同一區；webhook 要加驗證，不要裸奔；不要讓瀏覽器前端直接打，改由後端去打。

## Slack 流程

- 新開專用頻道，一個任務一個 thread；thread 裡只放當次交接：題目、受眾、job id、做到哪站、產出連結。
- skill 檔與流程定義本體在 repo，頻道只放連結跟討論——免費版 90 天就看不到了。
- 進度抓法：首頁送出拿 job id，每 2–3 秒打 `/api/status/<job id>`，後端讀 `jobs/<id>.json`（現在做到哪站、進度％、最後更新時間）；每站做完由該站 agent 或 n8n 更新該檔案。
